About Our Organization

Health and Education for All (HAEFA)

HAEFA is a US-based 501(c)(3) non-profit organization, enlisted in NGOAB of Bangladesh in the INGO category. It was founded by Dr. Ruhul Abid, a physician-researcher and medical scientist at the Warren Alpert Medical School, Brown University, USA — the bridge between HAEFA and DEWB @ Brown.

The Software

NIROG+ — Electronic Medical Record System

NIROG is a comprehensive EMR developed by HAEFA, in use in the FDMN camps, Noakhali and Cox's Bazar districts — and previously in the 2016 DFID program and the 2018 Grand Challenges Canada program.

Paperless, Barcode-Identified Records

Patient medical records are maintained digitally and retrieved using the digital health card's scannable barcode.

Works Offline

Solar-powered deployments that work without a constant internet connection — critical in the camps and remote upazilas.

Encrypted, Unique Identifiers

Tracks and records encrypted patient data under unique identifiers, giving doctors a high-technology resource for accurate follow-up care.

Simpler Chronic-Care Follow-Up

Follow-up of NCD, other chronic, and pregnant patients has become very simple for HAEFA due to this EMR.

Drug-Interaction Safety

Prevents drug interactions by suggesting contraindicated drugs — uniquely safe in emergency situations.

WHO ICD-10 Diagnoses

On the tablets, NIROG uses the WHO's Tenth Revision of the International Classification of Diseases to diagnose and standardize treatment and management protocols for NCDs.

Technology Stack

Under the Hood of NIROG+

Backend: Laravel (PHP) Frontend: ReactJS Database: Microsoft SQL Server Reporting: Google Looker Studio & Metabase Integrated with DHIS2 server

nirog-api

REST API (PHP / Lumen 9) serving the station UI — 17 controllers, one per clinic station.

nirog-backend

Admin CMS (PHP / Laravel 8) — 65 modules, including ~40 reference/lookup modules (drugs, diagnoses, vaccines).

nirog-frontend

Station UI (React 18 + Vite, Redux Toolkit) — one screen per clinic station, offline-capable with end-of-day sync.

Verified by DEWB from the source manifests: the database driver default is Microsoft SQL Server (sqlsrv) in both PHP apps — superseding the original README's claim of "MySQL or compatible database."

Registration

Consultation

Lab & Pharmacy

Investigations and prescriptions, with drug-interaction checking.

End-of-Day Sync

Offline writes sync from the clinic's local SQL Server to the central server.

Follow-Up

DEWB @ Brown — Our Work So Far

The Spring 2026 Engineering Partnership

DEWB (Doctors & Engineers Without Borders) at Brown University is working with HAEFA's Dhaka IT team on two named engineering challenges. Below is the partnership timeline and what we've verified to date.

Partnership Timeline

Sept–Oct 2025 — Compliance gate
DEWB engineering reaches out to Dr. Abid. HAEFA requires a signed HIPAA/Privacy & Confidentiality Agreement and the UN PSEA training certificate before any code access. Four members complete both.
23 Nov 2025 — The Dhaka demo
NIROG is introduced and the scope is named: improve daily synchronization so that only that day's data is synchronized, and improve synchronization at the upazila (sub-district) level.
Feb 2026 — Tooling blocker
dbForge Studio (the sync tooling) is paid software past its trial; no licenses available. A second NDA, gating source code specifically, is signed.
5 Mar 2026 — Code access granted
The brief, verbatim: "Database optimization: there are many duplicated tables and unused tables… Synchronization Performance Enhancement: the current synchronization process takes over one and a half hours to complete."
8 Apr 2026 — Sync artifacts
Mr. Chonchol sends the dbForge-generated batch files and custom.sql, noting SQL Server 2019.
Spring 2026 — Analysis
DEWB team tears down the sync scripts, maps all three codebases, and documents findings — with no changes to upstream code, which DEWB does not own.

What We've Verified

  • Stack: Lumen 9 API (17 station controllers), Laravel 8 CMS (65 modules), React 18 station UI, Microsoft SQL Server as the driver default.
  • Sync mechanism: end-of-day dbForge /datacompare batch jobs triggered from the CMS, copying clinic-local data to the central server.
  • The two asks, both open: (1) incremental "only today's data" sync, plus upazila-level sync; (2) schema cleanup of duplicate/unused tables.
  • Discipline: real patient data (PHI) is never copied into our repo or docs; upstream contributions go back as PRs to HAEFA's maintainer.
The ~90-minute sync baseline is HAEFA's figure; no timing has been measured by our team yet — that's the next milestone.
